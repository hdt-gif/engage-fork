PyPSA feature · power flow on the network

Will the island's lines carry this plan?

Engage treats power lines like pipes: power goes wherever it's cheapest, so a plan passes as long as some route fits. Real power splits across every path at once, so some lines carry more than their rating. PyPSA calculates that split, and can test the plan with any one line out of service.

PyPSA feature · stochastic optimization

Which plan holds up if the future doesn't go to plan?

Engage plans for one future: your inputs exactly. PyPSA can plan for several possible futures at once. It picks one build that has to keep the lights on in every future and costs the least on average, weighted by how likely each future is.

How this attaches to Engage
1 · Read the Engage model

A new Django app, alternatives, reads the run's locations, technologies, timeseries and costs from Engage's Postgres database and builds a pypsa.Network from them.

2 · Solve, then search near it

On the Celery worker Engage already uses, it solves for the cheapest plan with HiGHS, then reruns PyPSA's MGA, pushing each technology up and down within the cost margin.

3 · Show it on the run

All three features appear as this tab on the run. Alternatives come from PyPSA's MGA, the grid check from its linearised power flow with single-outage checks, and uncertain futures from its stochastic optimization.

In this prototype, a grid search in your browser stands in for PyPSA. It covers about 6,700 combinations on five representative days, with simplified dispatch, a made-up five-point island network and simplified DC power flow. Real PyPSA solves each of these as one optimization instead of trying every combination.
